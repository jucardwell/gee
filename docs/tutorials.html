3.7 Tutorial 7: Quality Masks and Image Preprocessing

//Satellite images often contain clouds, cloud shadows,or other poor-quality pixels.
//Most satellite datasets include one or more Quality Assurance (QA) bands that indicate the quality of each pixel.


//Here is an image of Chapel Hill
var image = ee.Image('LANDSAT/LC08/C02/T1_L2/LC08_016035_20230627');

//add a true-color visualization of the image to the map. 
//Do you notice the cloud cover?


//QA bands store information about each pixel using binary flags.
//Each binary digit is called a bit. A bit can either be 0 (false) or 1 (true).

//For the Landsat QA_PIXEL band:
//
//Bit 0 = Fill (valid pixel is 0)
//Bit 1 = Dilated Cloud
//Bit 2 = Cirrus
//Bit 3 = Cloud
//Bit 4 = Cloud Shadow


//If we wanted to determine whether a pixel contains a cloud, we would create
//a binary number with only Bit 3 turned on. 

var dialatedBit = 1 << 1;
var cirrusBit = 1 << 2;
var cloudBit = 1 << 3;
var shadowBit = 1 << 4;


//bitwiseAnd() compares this binary number to the QA band.
//If Bit 3 is turned on in the QA band, the result will be nonzero.

var cloud = qa.bitwiseAnd(cloudBit).eq(0);

//Display the cloud mask.

//Create masks for the remaining quality flags

//We can stack masks by using the following 
// var clearImage = cloud.and(SECONDCONDITION).and(THIRDCONDITION)...

//Write a command that stacks all the masks. 


//We can then apply that to the original image
//var masked = image.updateMask(clear);


//Display the masked image.


//This worked for one image. However, image collections hundreds or thousands
//of images. Rather than repeating this code for every image, we can write a function


var maskClouds = function(image){
  var qa = image.select('QA_PIXEL');
  var dilatedCloud = qa.bitwiseAnd(1 << 1).eq(0);
  var cirrus = qa.bitwiseAnd(1 << 2).eq(0);
  var cloud = qa.bitwiseAnd(1 << 3).eq(0);
  var shadow = qa.bitwiseAnd(1 << 4).eq(0);
  var snow = qa.bitwiseAnd(1 << 5).eq(0);
  var clear =
       dilatedCloud
      .and(cirrus)
      .and(cloud)
      .and(shadow)
      .and(snow);

  return image.updateMask(clear);
};


//Load a Landsat image collection over Chapel Hill.

var collection = ee.ImageCollection("LANDSAT/LC09/C02/T1_L2")
    .filterBounds(ee.Geometry.Point(-79.0558, 35.9132))
    .filterDate('2025-05-01', '2025-09-30');


//Apply the masking function to every image
//in the collection.

var cleanCollection = collection.map(maskClouds);

3.10 Tutorial 10: Spectral Indices, Thresholding, and Masking

//In the last tutorial, we learned how to create false-color composites
//using different Sentinel-2 bands to visualize features around Chapel Hill.

//While visualizations help us visually interpret satellite imagery, we often need
//quantitative measurements to analyze the landscape.

//Spectral indices allow us to mathematically combine different spectral bands
//to highlight specific land surface characteristics, such as vegetation,
//water, or burned areas.

//Remember our vegetation visualization
var image = ee.Image('COPERNICUS/S2_SR_HARMONIZED/20260313T160041_20260313T160757_T17SPV')

Map.addLayer(
    image, 
    {
        bands: ['B8', 'B4', 'B3'], 
        min: 160,
        max: 2500
    },
    'Vegetation' 
);

//In this false-color composite, healthy vegetation appears dark red because the
//near-infrared (NIR) band is displayed in the red channel. Since healthy vegetation
//reflects a large amount of NIR light, it stands out as shades of red.

//But what if we wanted to represent vegetation health mathematically? 
//We can use GEEs band math, where we combine multiple spectral bands using mathematical formulas

//One of the most widely used spectral indices is the Normalized Difference
//Vegetation Index (NDVI). NDVI compares the near-infrared (NIR) and red bands
//to estimate the presence and health of vegetation.

//Get bands
var nir = image.select('B8');
var red = image.select('B4');

//Calculate the numerator and the denominator using band subtraction and addition
var numerator = nir.subtract(red);
var denominator = nir.add(red);

//calculate NDVI.
var ndvi = numerator.divide(denominator);

//Add the layer
Map.addLayer(ndvi, {
    min: -1,
    max: 1,
    palette: ['red', 'white', 'green']
}, 'NDVI Manual');


//What NDVI values represent high vegetation? Which values represent low vegetation?

//Normalized differences like NDVI are so common in remote sensing that Earth Engine 
//provides the ability to do that particular sequence of subtraction, addition, and division 
//in a single step, using the normalizedDifference method.

//Now use the built-in normalizedDifference function to achieve the same outcome.
var ndviND = image.normalizedDifference(['B8', 'B4']);
Map.addLayer(ndviND, {
    min: -1,
    max: 1,
    palette: ['red', 'white', 'green']
}, 'NDVI normalizedDiff');

//NDVI gives us a continuous value of vegetation
//let's say that we want to categorize our data into highly vegetated and not highly vegetated
//to do this, we can use a threshold

//for instance, let's say that over .7 is highly vegetated. 

// Implement a threshold
//this will set anything above .7 as 1 and anything below as 0
var chVeg = ndviND.gt(0.7);

Map.addLayer(chVeg,
    {
        min: 0,
        max: 1,
        palette: ['white', 'green']
    },
    'Highly Vegetated');
    

// While binary classification is useful, we often want to classify an image
//into more than two categories. For example, we might want to identify
// areas with low, moderate, and high vegetation.

//We can do this using the .where() method which changes the value of pixels that
//satisfy a condition. By applying multiple .where() statements, we can
//build a classified image with several categories.

//Create a starting image where every pixel has a value of 1.
//This will represent areas with moderate vegetation.
var ndviClasses = ee.Image(1)
    .clip(ndviND.geometry());

//Assign pixels with NDVI values less than or equal to 0.3 to class 0.
ndviClasses = ndviClasses.where(ndviND.lte(0.3), 0);

//Assign pixels with NDVI values greater than or equal to 0.7 to class 2.
ndviClasses = ndviClasses.where(ndviND.gte(0.7), 2);

//Pixels with NDVI values between 0.3 and 0.7 remain class 1.

// Display the classified NDVI image.
Map.addLayer(ndviClasses,
    {
        min: 0,
        max: 2,
        palette: ['brown', 'yellow', 'green']
    },
    'Low, Moderate, High NDVI');


//Now suppose we only want to keep the highly vegetated areas.
//updateMask() uses another image (called a mask) to decide which pixels
//should remain visible.
//
// The mask (chVeg) contains:
//   1 = keep this pixel
//   0 = hide this pixel
//
// Since chVeg was created with ndviND.gt(0.7), only pixels with
// NDVI values greater than 0.7 have a value of 1.
//
// Applying updateMask(chVeg) keeps those pixels and hides all others.
// The NDVI values themselves do NOT change, only which pixels are displayed
// and included in later analyses.

var masked = ndviND.updateMask(chVeg);

Map.addLayer(masked,
  {
    min: 0,
    max: 1,
    palette: ['white', 'green']
  },
  'NDVI > 0.7');
