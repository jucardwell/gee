// Google Earth Engine's code editor allows us to access the 
//Earth Engine API. The Earth Engine API is very powerful and 
//contains methods to do most everything we would want to do in 
//terms of image processing and analysis

//Click on the "Docs" tab to the right. This documents all of the 
//available functions in the Earth Egnine API. 

//the API functions have the prefix ee (for Earth Engine)

//API functions are "server-side" meaning that the processing
//will take place on Google's servers, as opposed to your
//local computer (client-side).

//Much of the power of Earth Engine is the ability to use Google's servers
//for processing. Therefore, we should be using "server-side" 
//functions as much as possible. 


//Let's look at a simple example. We can do basic arithmetic 
//on the server-side or the client side. 

//The client side looks like this
var client = 2 + 2;
print(client);

//The server side uses an API function and looks like this
var server = ee.Number(2).add(2);
print(client);

//The client side looks a little simpler, and in this example, they
//work at a similar speed. But for advanced processing, server-side
//functions are the only way to achieve something. It is best
//practice to get used to using server-side functions. 

// Now, let's explore more common server-side functions.

// Math Operations
// We can perform many other math operations using server-side functions

var num1 = ee.Number(10);
var num2 = ee.Number(5);

var addition = num1.add(num2);
var subtraction = num1.subtract(num2);
var multiplication = num1.multiply(num2);
var division = num1.divide(num2);

print(addition);
print(subtraction);
print(multiplication);
print(division);

// Logical Operations
// We can also perform logical operations

var isEqual = num1.eq(num2);
var isGreater = num1.gt(num2);
var isLess = num1.lt(num2);

print(isEqual);
print(isGreater);
print(isLess);

// Lists
// we can create lists on the server-side by adding the ee. 
//before the list function

var numbers = ee.List([1, 2, 3, 4, 5]);
print(numbers);

// Reduce a list
// Let's find the sum of the numbers in the list
var sum = numbers.reduce(ee.Reducer.sum());
print(sum);

//Sort a list in ascending and descending order.
var unsortedList = ee.List([10, 2, 30, 5, 7]);
var sortedListAsc = unsortedList.sort();
print(sortedListAsc);


// Filter elements in a list based on a condition.
var filteredList = unsortedList.filter(ee.Filter.gt('item', 5));
print(filteredList);

// Count the number of elements in a list.
var countElements = unsortedList.size();
print("Number of elements:", countElements);

3.9 Tutorial 9: Spectral Indices, Thresholding, and Masking


// In the previous tutorial, we learned how to create false-color composites
// using different Sentinel-2 bands to visualize features around Chapel Hill.

// While visualizations help us visually interpret satellite imagery, we often need
// quantitative measurements to analyze the landscape.

// Spectral indices allow us to mathematically combine different spectral bands
// to highlight specific land surface characteristics, such as vegetation,
// water, or burned areas.


//Remember our vegetation visualization
var image = ee.Image('COPERNICUS/S2_SR_HARMONIZED/20260313T160041_20260313T160757_T17SPV')

Map.addLayer(
    image, 
    {
        bands: ['B8', 'B4', 'B3'], 
        min: 160,
        max: 2500
    },
    'Vegetation' 
);

// In this false-color composite, healthy vegetation appears dark red because the
// near-infrared (NIR) band is displayed in the red channel. Since healthy vegetation
// reflects a large amount of NIR light, it stands out as shades of red.


//But what if we wanted to represent vegetation health mathematically? 
// We can use GEEs band math, where we combine multiple spectral bands using mathematical
// formulas to highlight specific land surface characteristics.

// One of the most widely used spectral indices is the Normalized Difference
// Vegetation Index (NDVI). NDVI compares the near-infrared (NIR) and red bands
// to estimate the presence and health of vegetation.

// Extract the near infrared and red bands.
var nir = image.select('B8');
var red = image.select('B4');

// Calculate the numerator and the denominator using subtraction and addition respectively.
var numerator = nir.subtract(red);
var denominator = nir.add(red);

// Now calculate NDVI.
var ndvi = numerator.divide(denominator);

// Add the layer to our map with a palette.
Map.addLayer(ndvi, {
    min: -1,
    max: 1,
    palette: ['red', 'white', 'green']
}, 'NDVI Manual');


//What NDVI values represent high vegetation? Which values represent low vegetation?

//Normalized differences like NDVI are so common in remote sensing that Earth Engine 
//provides the ability to do that particular sequence of subtraction, addition, and division 
//in a single step, using the normalizedDifference method.

// Now use the built-in normalizedDifference function to achieve the same outcome.
var ndviND = image.normalizedDifference(['B8', 'B4']);
Map.addLayer(ndviND, {
    min: -1,
    max: 1,
    palette: ['red', 'white', 'green']
}, 'NDVI normalizedDiff');

//NDVI gives us a continuous value of vegetation
//let's say that we want to categorize our data into highly vegetated and not highly vegetated
//to do this, we can use a threshold


//for instance, let's say that over .7 is highly vegetated. 

// Implement a threshold
//this will set anything above .7 as 1 and anything below as 0
var chVeg = ndviND.gt(0.7);

Map.addLayer(chVeg,
    {
        min: 0,
        max: 1,
        palette: ['white', 'green']
    },
    'Highly Vegetated');
    
// So far, we've used a threshold to divide our NDVI image into two classes:
// highly vegetated (1) and not highly vegetated (0).

// While binary classification is useful, we often want to classify an image
// into more than two categories. For example, we might want to identify
// areas with low, moderate, and high vegetation.

// We can do this using the .where() method.
//
// Rather than hiding pixels, .where() changes the value of pixels that
// satisfy a condition. By applying multiple .where() statements, we can
// build a classified image with several categories.

// Create a starting image where every pixel has a value of 1.
// This will represent areas with moderate vegetation.
var ndviClasses = ee.Image(1)
    .clip(ndviND.geometry());

// Assign pixels with NDVI values less than or equal to 0.3 to class 0.
ndviClasses = ndviClasses.where(ndviND.lte(0.3), 0);

// Assign pixels with NDVI values greater than or equal to 0.7 to class 2.
ndviClasses = ndviClasses.where(ndviND.gte(0.7), 2);

// Pixels with NDVI values between 0.3 and 0.7 remain class 1.

// Display the classified NDVI image.
Map.addLayer(ndviClasses,
    {
        min: 0,
        max: 2,
        palette: ['brown', 'yellow', 'green']
    },
    'Low, Moderate, High NDVI');


// Now suppose we only want to keep the highly vegetated areas.
//
// updateMask() uses another image (called a mask) to decide which pixels
// should remain visible.
//
// The mask (chVeg) contains:
//   1 = keep this pixel
//   0 = hide this pixel
//
// Since chVeg was created with ndviND.gt(0.7), only pixels with
// NDVI values greater than 0.7 have a value of 1.
//
// Applying updateMask(chVeg) keeps those pixels and hides all others.
// The NDVI values themselves do NOT change, only which pixels are displayed
// and included in later analyses.

var masked = ndviND.updateMask(chVeg);

Map.addLayer(masked,
  {
    min: 0,
    max: 1,
    palette: ['white', 'green']
  },
  'NDVI > 0.7');
